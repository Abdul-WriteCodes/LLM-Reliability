# Blind manual annotation rubric for Research 002

Do not provide reviewers model names, prompt conditions or ground-truth outcomes before coding. Assign shuffled, anonymized response IDs. Use the original WDI table and source indicator definitions when checking assertions; never treat the LLM's own text as ground truth.

Each CSV row generated by `python scripts/grade.py` is an LLM response. Two annotators should score all 6 evidence-limits items, plus a prespecified random sample of numeric/directionality answers, independently.

For each row, use 1=yes, 0=no, and blank=not yet coded. Columns:

- `human_correct`: 1 only if the principal requested answer is justified by the supplied table. On `evidence_limits`, the correct answer must say that the three indicators alone cannot establish the proposed welfare/causal claim. Explanations that contain unsupported factual claims should be flagged separately.
- `unsupported_claim`: 1 if the response asserts at least one concrete economic claim lacking support from the supplied evidence. Merely describing a possibility/hypothesis is not automatically an unsupported assertion.
- `contradicted_data`: 1 if a claim directly conflicts with a number or trend in the supplied table.
- `fabricated_statistic`: 1 if the response reports a specific numeric statistic that is neither in the table nor legitimately derived from it (unless clearly marked hypothetical).
- `unjustified_causality`: 1 if it asserts a causal explanation based solely on the descriptive table.
- `appropriate_abstention`: on evidence-limit items, 1 if the model correctly refuses to infer the requested unsupported outcome, rather than giving an unsupported yes or no. On answerable items, refusal is generally inappropriate and should be recorded in notes.
- `notes`: paste the exact offending claim and explain the reference evidence, or explain why the response was appropriate.

Keep mutually compatible flags: a fabricated statistic can also be an unsupported claim; an unsupported claim need not be fabricated. Avoid interpreting a correlation or accounting identity as causal identification.

**Malformed JSON and missing numeric fields:** In the updated grader, missing/invalid structured numeric or yes/no answers count as incorrect for the automated question (rather than disappearing from the accuracy denominator). Report `parse_error` rates separately. Do not count HTTP failures as factual mistakes: the runner logs them separately and attempts reruns.

**Analysis:** Report accuracy separately for 12 numerical and 12 binary questions. Report evidence-limit recognition and unsupported-claim rate separately; produce 30-question overall accuracy only after manually evaluating those 6 answer types. Use question IDs as clusters or paired units when comparing A/B/C; repeated calls are not 810 independent questions. Present per-item uncertainty and raw counts as well as rates. Consider annotator agreement before adjudication.

**Protocol change:** If switching the grader to count invalid answers as incorrect differs from a prior preregistration, disclose this change before formal runs. Freeze the scoring rubric before the main experiment.
